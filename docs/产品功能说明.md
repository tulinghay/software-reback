# software-reback 产品功能说明

> **面向使用者**的产品文档。它讲的是：这个工具为什么存在、能给你什么、你会怎么用它、以及它的边界在哪。
> 技术实现（架构、接口、隔离机制）在 [`02-architecture.md`](02-architecture.md)、[`03-api-contract.md`](03-api-contract.md) 等工程文档里，本文不展开。
>
> **状态说明**：本文描述的是产品的目标形态。标注 ✅ 的能力在早期版本即可用；标注 🚧 的能力属于完整蓝图的一部分，会随后续版本交付。下面的每一节都会标清楚，你读到时不至于误解。

## 一、它解决什么问题

每次重装 Windows，真正消耗人的不是装系统那二十分钟，是装完之后：

- **想不起来原来装了什么。** 几十个软件，只记得最常用的那几个，剩下的靠翻截图、翻回收站、靠记忆慢慢捞。
- **想起来了还得挨个找。** 打开浏览器，搜官网，分辨哪个是真官网，找到下载页，再找对版本。
- **下到的东西不干净。** 第三方「软件大全」站、被改过的安装包、捆绑了别的东西的版本 —— 装完才发现多了一堆东西。
- **存着的安装包也过期了。** 硬盘里那堆两年前的 exe，装上去版本落后一大截，还不如重新下。

这个工具把这件事压缩成两步：

```
重装前  →  扫一遍这台电脑：装了什么、什么版本  →  清单一存在（本地或云端）
重装后  →  按清单把安装包批量取回来            →  下载目录里一堆官方安装包
```

它的设计目标很克制，也非常明确：

> **把「重装后逐个软件去官网找下载」这件事，从几十次重复劳动，变成一次确认 + 一次批量下载。**

## 二、产品定位与设计原则

这几条决定了它长成什么样，也是理解后面所有功能的前提。

| 原则 | 含义 | 对你意味着什么 |
|---|---|---|
| **只取回，不代装** | 工具负责把安装包下回来，安装动作交给你 | 你永远保留「这个我不装了」的选择权，不存在「它偷偷帮我装了什么」 |
| **只认登记过的来源** | 下载地址必须来自「软件目录」或已识别的包 ID，不接受临时输入的 URL | 你填什么它下什么，把关权在你手上，同时避免被钓鱼链接诱导 |
| **宁漏不误** | 匹配不到唯一来源时，宁可标记为「跳过」，也绝不猜一个可能就是错的包 | 它可能会漏掉一些软件交给你手动处理，但不会给你装错软件 |
| **不托管安装包** | 只记录「官网在哪」和「校验值」，不自己存一份安装包再分发 | 多数软件许可协议禁止再分发；同时这也是它不需要额外存储空间的原因 |
| **清单是隐私** | 软件清单能反推你的使用习惯、职业、装机习惯 | 清单默认不进版本库，不公开分享 |

## 三、核心概念（看懂这五个词就够了）

| 概念 | 是什么 | 打个比方 |
|---|---|---|
| **清单（inventory）** | 一台机器上装了哪些软件的记录，就是一份 `software.json` | 你的**存货记录** |
| **软件目录（catalog）** | 一张「软件名 → 去哪下、校验值是多少」的对照表 | 你的**货源手册** |
| **来源（source）** | 某个软件最终从哪下：官网直链，还是 winget 包 | 具体的**发货渠道** |
| **下载计划（plan）** | 正式下载前，工具为每个软件算出的「从哪下、怎么验」 | 出发前的**采购清单** |
| **下载报告（report）** | 跑完之后每个软件的结果：成功 / 失败 / 跳过，及原因 | **签收单** |

一次完整的重装，就是让这五个东西依次流转一遍。

产品由四个能力模块组成。下表是全景，后面逐节展开。

| 模块 | 一句话职责 | 解决你的什么痛点 | 状态 |
|---|---|---|---|
| **软件读取** | 自动识别这台电脑装了哪些软件 | 「记不住装了什么」 | ✅ 早期版本可用 |
| **软件下载** | 按清单把安装包批量取回本地 | 「挨个找官网」「版本搞错」 | ✅ 早期版本可用 |

## 五、功能一：软件读取

### 你得到什么

一条命令，拿到这份电脑上装了什么的完整记录：

```
已读取 55 个软件，清单写入：software.json
```

清单里每个软件包含：**软件名、版本号、发行商、安装位置**。这份记录和系统「设置 → 应用 → 已安装的应用」同源，所以你看了会觉得眼熟、能对上。

### 它会自动做的四件事

| 行为 | 为什么重要 |
|---|---|
| **多来源扫描** | 同时读 64 位安装项、32 位安装项、当前用户安装项。只读一处会漏掉一大半软件 |
| **过滤噪音** | 自动剔除系统组件、补丁更新、补丁子项。否则清单里会混进几十条 `KBxxxxx` 让你无从下手 |
| **去重合并** | 同一软件同时装了 32/64 位两份时，合并成一条，缺失的信息互相补齐 |
| **区分安装范围** | 标明是「全机器安装」还是「仅当前用户安装」。重装后你会需要这个信息来判断该装到哪 |

### 你可以在清单里做的手动调整

清单就是一份 JSON 文件，**你可以直接编辑它**：

- **删掉不想重装的**（临时装的测试工具、一次性软件）；
- **补上漏掉的**（有些软件写在别的位置，工具没读到）。

删了就一定不会被下载 —— 这让「清单」同时成为你的**重装白名单**。

### 🚧 蓝图里更强的识别能力

完整方案会在读取环节再加两层识别，目标是让**大多数软件不需要你手动补地址**：

- 优先使用系统包管理器自己记录的**精确包标识**，而不是靠软件名去猜；
- 识别应用商店类应用，把这类应用单独分类（它们不该走下载流程，重装后从商店的「我的应用」还原更可靠）；
- 把「运行时组件」（各种运行库、框架）和「真正的应用软件」分开标注，你可以只关心后者。

> 为什么要分开？因为一台机器的清单里常有相当比例的条目其实是运行库，它们不是你「记得要装」的软件。分开之后你看到的才是真正要处理的。
> （蓝图文档记录了实测数据：某台 Win11 机器 55 条记录里有 16 条是运行时/平台组件，真正的应用约 36 个。）

## 六、功能二：软件下载

### 你会怎么用它

下载分两步走，**第二步强烈建议不要跳过**。

**第一步：先预览计划**

```
python -m software_reback download -i software.json -d downloads --dry-run
```

这一步**不会下载任何东西**，只告诉你：每个软件打算从哪下、用什么方式、能不能下。

**第二步：确认后真下**

```
python -m software_reback download -i software.json -d downloads
```

安装包落到你指定的目录里。

### 下载来源的优先级

工具按这个顺序为每个软件找来源，前一个不行才用后一个：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | **软件目录里的官方直链** | 最可控。可以带校验值，最适合包管理器覆盖不到的软件 |
| 2 | **清单里已经识别的包 ID** | 包管理器上一轮已经精确匹配到的 |
| 3 | **按名称自动匹配** | 最后一道自动兜底 |
| 4 | **匹配不到 → 进人工清单** | 明确告诉你「这个我搞不定」，而不是猜 |

### 你会拿到的报告

跑完生成一份 `download-report.csv`，Excel 能直接打开（不乱码）。每个软件一行，重点看 `status` 列：

| status | 意思 | 你要做什么 |
|---|---|---|
| `ok` | 下载成功 | 按 `target` 列路径去拿文件 |
| `planned` | 只是计划，没真下 | 正常（你跑的是预览） |
| `failed` | 下载失败 | 看 `detail` 列原因 |
| `skipped` | 找不到来源 | **需要你补目录，或手动下**（见第八节） |

### 内置的安全行为

| 行为 | 作用 |
|---|---|
| **强制校验** | 目录里登记了校验值的软件，下载完自动比对。对不上就判失败 |
| **失败不留残骸** | 先写临时文件，校验通过才改名为正式文件。校验失败时临时文件会被删掉，你不会拿到半个文件 |
| **单点失败不中断整批** | 一个软件下载失败，不会让剩下的全停下 |
| **失败有明确信号** | 有失败项时命令返回非零退出码，方便接脚本判断 |

### 🚧 蓝图里更强的下载能力

| 能力 | 解决什么 |
|---|---|
| **断点续传** | 大文件（几个 G 的镜像、游戏启动器）下到一半断了不用从头开始 |
| **并发与限速** | 多个软件同时下，但可以设一个总速率上限，不把家里网络占满 |
| **失败自动重试** | 网络抖动自动退避重试几次，不用你手动重跑 |
| **缓存复用** | 同一个安装包以前下过、校验值也对得上，直接跳过，不重复下载 |
| **清单从云端拉取** | 重装后不需要提前拷文件，登录即可取回清单 |

## 七、功能三：清单的云端保存与隔离

这是完整蓝图里的能力。现在（早期版本）清单是本地文件，**重装前你需要自己把文件拷到 U 盘或网盘**。

### 它解决什么问题

本地文件方案有两个硬伤：

1. **重装会清空本地磁盘**，清单必须提前手动转移，忘了就没了；
2. **多台机器、多人使用时容易串** —— A 的清单被 B 覆盖，或者重装前那台机器的清单被重装后那台覆盖掉。

云端保存解决的正是这两点。

### 你会怎么用它

```
重装前  →  登录，把清单上报到云端（自动记录「这是哪台机器」）
重装后  →  在新机器上登录，拉回「重装前那台机器」的清单
```

### 隔离性，以及你能怎么验证它

这是这个能力最需要被信任的部分，所以单独说明：

**双维度隔离。** 每份清单同时归属到「**哪个账号**」和「**哪台机器**」两个维度：

- 同一账号下有多台电脑 → 各自的清单**互相独立**，不会互相覆盖；
- 重装前那台机器和重装后这台机器 → 是两条独立记录，随时能取回重装前那一份；
- 不同账号之间 → 完全隔离，互相不可见、不可读写。

**怎么证明它真的隔离了。** 设计上不满足于「代码里记得加了过滤条件」，而是要求**越权行为被系统性拒绝**，并且有一套**可自动复现的验证用例**覆盖：伪造他人凭证、篡改资源标识读别人的清单、跨账号读/写/列举、枚举他人数据、企图用拼接路径逃出自己目录、并发写入时互相污染。

这些用例不是纸面承诺 —— 它们是可执行的测试，随代码一起运行。验收标准是**越权拦截率 100%**：每一条尝试越权的用例都必须被拒绝，且拒绝记录会落进审计日志。

> 换句话说：**「不串」不是一个说法，是一个能跑出结果来的检查项。**

### 与隔离配套的几个设计

| 设计 | 为什么 |
|---|---|
| **失败时宁可报错，不降级** | 云端连不上时，绝不「悄悄回退到上一次的清单」或「用个空账号目录顶上」—— 那正是串数据的来源。宁可明确报错让你知道 |
| **敏感信息不落明文** | 凭证只存摘要不存原文，日志里自动打码 |
| **共享目录的写入受限** | 软件目录是全用户共享的，但普通人只能「提交建议」，不能直接改；提交的地址还要过安全校验（拒绝可疑协议、拒绝内网地址） |
| **操作可追溯** | 每次读写都有记录，出问题能查 |

## 八、功能四：软件汇总（软件目录）

### 为什么需要它

这是最容易被低估、但实际上决定工具好不好用的部分。

现实是：**光靠包管理器，只能自动解决一部分软件。** 商业软件（微信、QQ、Office）、国内软件、以及包管理器没有收录的工具，都需要一个地方记录「它的官方下载地址是什么」。

这个「地方」就是软件目录。

> 产品能力的天花板，主要取决于软件目录有多完整，而不是代码有多聪明。**用得越久、补的地址越多，它就越好用。**

### 目录里记什么

每个软件一条记录，核心是这几项：

| 字段 | 作用 |
|---|---|
| **软件名** | 匹配键。名字对不上就等于没登记 |
| **官方下载地址** | 从哪下 |
| **校验值（SHA256）** | 怎么确认下到的没被调包。**强烈建议填** |
| **包标识**（可选） | 如果走包管理器，记它 |
| **静默安装参数**（可选） | 备查，工具本身不代装 |

### 你怎么补一条

复制示例文件，加一条记录即可：

```json
{
  "entries": [
    {
      "display_name": "微信",
      "url": "https://dldir1.qq.com/weixin/Windows/WeChatSetup.exe",
      "file_name": "WeChatSetup.exe",
      "sha256": "官方安装包的真实 SHA256"
    }
  ]
}
```

规则只有三条：

1. **`display_name` 必须和清单里的名字对得上**（忽略大小写和多余空格）。不确定就从清单里直接复制。
2. `url` 和包标识**至少给一个**。
3. 校验值可以为空，但**填了就会强校验**；空着等于放弃这道防线。

算校验值（PowerShell）：

```powershell
certutil -hashfile .\WeChatSetup.exe SHA256
```

补完带上目录参数重跑：

```
python -m software_reback download -i software.json -d downloads --catalog catalog.json
```

### 去哪找官方地址

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | **软件官网** | 最可靠 |
| 2 | 官方 GitHub Releases | 开源软件常用，认准 Releases 页 |
| 3 | 微软商店的桌面应用页面 | 有时能拿到官方直链 |
| ❌ | 「绿色版」「破解版」「软件大全」站 | **不要用**，这是恶意软件的主要传播渠道 |

> 判断一个站是不是官网，一个简单办法：从软件的**关于/帮助**菜单里找「官方网站」链接，而不是靠搜索结果排序。

### 🚧 蓝图里更强的目录能力

| 能力 | 解决什么 |
|---|---|
| **多来源自动采集** | 从包管理器元数据自动抓取下载地址与校验值，减少手工填写 |
| **别名匹配** | 「微信 / Weixin / WeChat」这类多个名字指向同一个软件，不会因为叫法不同就漏掉 |
| **链接健康度检测** | 定期检查目录里的地址还能不能用，失效的打上标记，而不是等你去下的时候才发现 404 |
| **社区贡献与审核** | 一个人补的地址，其他人也能用；但入库前要过自动安全校验和审核，防止投毒 |
| **增量同步** | 目录更新时只同步变化的部分，不用每次全量拉 |

## 九、完整使用流程（重装一条龙）

把四个模块串起来，一次重装长这样：

| 阶段 | 你做什么 | 工具做什么 |
|---|---|---|
| **准备** | 确认清单里没漏 | 扫描本机，生成清单 ✅ |
| **整理** | 打开清单，删掉不想重装的 | — |
| **预览** | 跑预览，看哪些没着落 | 算出每个软件的下载计划 ✅ |
| **补漏** | 对「跳过」的软件，补目录地址 | — |
| **备份** | 把清单（和目录）存到 U 盘/网盘；蓝图版可上传云端 🚧 | — |
| **重装** | 装系统 | — |
| **取回** | 新机器上登录，拉回清单 🚧 | 云端返回「重装前那台机器」的清单 🚧 |
| **下载** | 跑下载 | 批量下载 + 校验 ✅ |
| **安装** | **你双击安装** | 不参与 |

最后一步永远是手动。这是刻意设计，见下一节。

## 十、它刻意不做什么

这一节不是「以后会做」，是**设计上的取舍**。了解原因能帮你正确预期。

| 不做 | 为什么 |
|---|---|
| **不自动安装** | 「下载完就自动执行」等于把任意代码执行的风险塞进工具。安装包下回来后由你双击，你始终保留最后一道确认 |
| **不托管、不再分发安装包** | 多数软件许可协议禁止再分发。工具只记录官网地址与校验值，不帮你存副本 —— 这也是它不需要额外存储空间的原因 |
| **不接受临时输入的下载地址** | 只认登记过的来源，避免被诱导下载任意文件 |
| **不下应用商店类应用** | 商店包需要额外授权、拉取易失败。这类应用重装后从商店「我的应用」还原更可靠 |
| **不迁移驱动、系统设置、环境变量、字体、开发环境** | 和「软件清单」不是一类问题，混进来会把工具做糊。这类需求建议单独处理 |
| **不判断地址安不安全** | 它只负责下载和校验。地址的可信度由你（或目录审核流程）把关 |
| **不做静默批量安装** | 同上，把「装什么、装不装」的决定权留给你 |

## 十一、常见问题

**Q：扫描出来的软件比实际装的少？**

三种情况：① 系统组件和补丁被自动过滤了（这是对的）；② 有些软件写在注册表其他位置，当前不读；③ 商店应用不在注册表里。可以手动往清单里补一条。

**Q：为什么有些软件显示「跳过」？**

说明工具找不到可信的下载来源。这不是故障，是「宁漏不误」原则在起作用 —— 它宁可交给你处理，也不猜一个可能错的下下去。解决办法是在目录里补一条记录。

**Q：能只下载我挑的几个软件吗？**

可以。清单就是白名单，把不要的条目删掉再跑下载即可。

**Q：清单含隐私信息吗？**

含。软件名称和安装位置能反映使用习惯。清单默认不进版本库，**不要公开分享**。

**Q：同一份清单能在别的电脑上用吗？**

可以。它是目标清单，不绑定原机器 —— 拷过去直接跑下载即可。

**Q：大文件下到一半断了怎么办？**

早期版本需要重下。蓝图版本会支持断点续传。

**Q：报告里的 `failed` 都是什么原因？**

常见的是：下载源在当前网络下不可达、校验值不匹配、地址已失效。看 `detail` 列，通常能直接看出是哪种。链接失效的，往目录里补一个新地址即可。

**Q：它会不会把我原来装的软件搞坏？**

不会。它只读不写 —— 读取阶段只读注册表，下载阶段只往你指定的目录写文件。**它从不修改已安装的软件。**

## 十二、重装前的检查清单

照着打勾即可：

- [ ] 跑过扫描，清单已生成
- [ ] **打开清单检查过**，删掉了不想重装的条目
- [ ] 跑过预览，知道哪些软件是「跳过」状态
- [ ] 对「跳过」的软件，要么补进了目录，要么记在别处准备手动下
- [ ] 如果补了目录，**带上目录参数完整跑了一遍真实下载**
- [ ] 下载目录里有你需要的安装包
- [ ] **清单、目录、下载目录都已备份到 U 盘或网盘**（蓝图版可上传云端）
- [ ] 顺便把这个工具本身也备份了一份

> 最后一条最容易被忘：重装后系统是干净的，工具本身也得重新拿回来。

---

## 十三、安全使用建议

1. **目录地址只写官方站。** 工具不会判断地址安不安全，这一步的把关在你。
2. **校验值能填就填。** 这是唯一能防住「链接被调包」的机制。不填也能下，但等于放弃防线。
3. **安装包装之前扫一下**，尤其是来源不熟悉的。
4. **清单别公开。** 它含隐私。
5. **别用来下载破解版。** 工具的定位是「官方来源的可靠取回」，不是「什么都能下的下载器」。

---

## 十四、一句话总结

> **它把「重装后挨个软件去官网找下载」变成「重装前确认一份清单，重装后批量取回」。**
>
> 它不替你装，也不替你判断地址可不可信 —— 它只把「找地址、翻官网、怕下错」这件重复劳动去掉，剩下的决定权都留给你。

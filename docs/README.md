## 三条核心结论（可直接引用）

1. **读取覆盖率可以大幅提升，而且不靠猜**：现状「按名称搜 winget」只有 25%（14/55）；改用 `winget export` 的**精确包 ID** 后，本机 55 条能关联到 **50 条 = 90.9%**。这是本项目最大的一处纠偏，详见 `06` §2.3。
2. **隔离是可自动证明的**：不是「代码里记得加 `where`」，而是「不加 `where` 就查不出数据」——SQL 谓词 + 统一 `assert_owned` + 35 条负面用例（伪造 token / 跨账号 / 跨设备 / 枚举 / 投毒 / 重放 / 并发），跑 `python -m unittest discover -s tests` 即自证，见 `04` §4–§5。
3. **云端要轻**：notebook 只有 11G 内存且已用 5G、跑了 27 个容器。方案是一条 `systemd --user` 单进程 + SQLite（常驻 < 100MB），不引入 Docker、不动现有服务，见 `02` §2、§5。

## 已知待决事项（评审时需要拍板）

以下 4 处是四路并行设计后发现的口径冲突，已在各文档中原位标注；**建议在 M0「契约冻结」阶段一次性定案**：

| # | 冲突 | 建议裁决 | 影响面 |
|---|---|---|---|
| 1 | **跨账号越权返回 404 还是 403**：`03` 定为 403 `E_FORBIDDEN`，`04` 定为 404 `resource_not_found`（防枚举） | 采用 **404**（`04` 的理由更充分：避免资源存在性侧信道），`03` 的错误码表改一行 | 接口契约 + 35 条用例中的 N1–N3 |
| 2 | **`device_id` 由谁生成**：`01` 写「客户端首次生成」，`04` 写「服务端生成、不由客户端自报」 | 采用 **服务端签发**（客户端自报的 ID 可被伪造重放） | 注册流程 + D3/D5 用例 |
| 3 | **account_id 前缀**：`03` 用 `acc_`，`04` 用 `acct_` | 统一为 **`acct_`** | 仅示例可读性 |
| 4 | **`winget list` 行数口径**：`153` 数据行 vs `155` 总行数（含表头前空行） | 统一表述为「**155 行原始输出 / 153 行数据**」 | 指标与 fixture 断言 |

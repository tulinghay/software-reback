## 三条核心结论（可直接引用）

1. **读取覆盖率可以大幅提升，而且不靠猜**：现状「按名称搜 winget」只有 25%（14/55）；改用 `winget export` 的**精确包 ID** 后，本机 55 条能关联到 **50 条 = 90.9%**。这是本项目最大的一处纠偏，详见 `06` §2.3。
2. **隔离是可自动证明的**：不是「代码里记得加 `where`」，而是「不加 `where` 就查不出数据」——SQL 谓词 + 统一 `assert_owned` + 35 条负面用例（伪造 token / 跨账号 / 跨设备 / 枚举 / 投毒 / 重放 / 并发），跑 `python -m unittest discover -s tests` 即自证，见 `04` §4–§5。
3. **云端要轻**：notebook 只有 11G 内存且已用 5G、跑了 27 个容器。方案是一条 `systemd --user` 单进程 + SQLite（常驻 < 100MB），不引入 Docker、不动现有服务，见 `02` §2、§5。

## 评审结论：云端定位需要重新确认（重要）

这一节是对整体设计的**反思性评审**，不是对已定案内容的推翻，而是指出一个需要在 M1 开工前由项目负责人确认的前提问题。

### 问题：云端解决的不是原始需求

原始需求是「**重装 Windows 前记下装了什么，重装后取回**」。这个需求的完整闭环是：

```
本机 scan → 本地 software.json → 重装 → 本机 download
```

**全程不需要网络服务。** 而当前设计把 `cloud push` / `cloud pull` 插进主流程（`01-features.md` §8 第 4–7 步），使云端成为必经环节。

但 `02-architecture.md` 的决策 D10 自己承认：

> 提供 `cloud push` 的离线兜底：先落本地 `software.json`，再上报；上报失败只告警不阻塞

**如果本地文件已经能兜底，云端就不是必需的。** 云端真正解决的是另外两个需求：

| 云端真正解决的问题 | 是否原始需求 |
|---|---|
| 换机迁移（A 机清单 → B 机还原） | 否，是后续衍生 |
| 多人各自维护、互不干扰 | 否，是后续衍生（M3 隔离整个模块就是为它服务的） |

### 影响：两个里程碑的投入产出比需要重估

| 里程碑 | 工作量（预估） | 若云端非必需，则 |
|---|---|---|
| M1 云端骨架与隔离 | 5–7 人日 | 可推迟；主流程用本地文件即可闭环 |
| M3 下载强化 | 4–6 人日 | **仍然必需**（续传、重试、并发与云端无关） |
| M4 目录运营 | 6–8 人日 | **仍然必需**（补 winget 覆盖不到的尾巴是核心价值） |

也就是说：**M1 的 5–7 人日可以被推迟，而 M2/M3/M4 的价值不受影响**。如果先做 M2 + M3 + M4（13–19 人日），能得到一个**完全本地、无服务端依赖、可立即使用**的工具；云端可以在确认「确实需要换机/多人」之后再补。

### 隔离设计的复杂度与真实场景的匹配度

`02-architecture.md` 风险表已自认：

> 单机单账号场景下的隔离过度设计 → 多一层 `device_id` 校验，调试与上手成本上升

`04-isolation.md` 的 35 条越权用例、`assert_owned`、`INV-1~4`、审计日志、`SqlHygieneTest`、覆盖率门槛——这套设计的**质量很高**，但它服务的是「多用户共享一个服务端」的场景。如果实际用户只有一个人（当前代码与文档的所有实测数据都来自单机单账号），这套复杂度没有对应收益。

文档给出的缓解措施是「提供一键生成并保存 `device_id` 的命令」——这只降低了**使用成本**，没有降低**设计复杂度**。

### 建议的决策点（需项目负责人确认）

| 选项 | 含义 | 后续影响 |
|---|---|---|
| **A（建议）** | 先做 **M2 + M3 + M4**，云端推迟到确认需要换机/多人后再做 | 13–19 人日拿到可用工具；文档 02/03/04 保留但标记「未启动」 |
| B | 按原路线 M0→M1→M2→M3→M4 全做 | 23–33 人日；隔离设计完整，但可能为不存在的场景付费 |
| C | 只做 M1 的最小集（`/healthz` + push/pull，**不做** 35 条越权矩阵与审计） | 约 2–3 人日；满足换机需求，牺牲隔离的「可证明性」 |

> 本节不改变 `01`~`07` 任何已定案的接口与字段。它只是把「云端是否现在就该做」这个前提问题显式提出来——原文档把它当作既定前提，而 D10 的兜底设计与风险表的自我承认，都在提示这个前提值得复核。
